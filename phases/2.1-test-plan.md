# Phase 2.1: Test plan

## Inputs

- `REQUIREMENTS.md`, `DESIGN.md`, optional `ARCHITECTURE.md`
- `PLAN.md` (chunk list)

## Steps

1. **Dispatch QA** with inputs.
   - QA drafts `TEST.md` from `templates/artifacts/TEST.md.tpl`.
   - Sets coverage targets (per-project, per conventions/testing.md).
   - Identifies inference-driven components; adds the "Inference coverage" section if any.

2. **File-backup safety check.** PM identifies any chunk that will modify existing code; QA drafts the backup strategy for those files (per `TEST.md.tpl` Backup strategy table).

3. **G4: TEST.md + backup-strategy approval.**
   - Type A gate.
   - Present: TEST.md path + 3-5 bullets + backup-strategy table.
   - Recommendation: "approve and proceed to implementation".
