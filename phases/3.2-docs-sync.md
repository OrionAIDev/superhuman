# Phase 3.2: Docs sync

## Inputs

- SUPERHUMAN.md `## Declared artifacts` list
- All declared artifacts on disk
- Implementation state (commits, test results)

## Steps

1. **Triage scan.** PM reads stat-list (path + last-modified + size) for every declared artifact. Identify any that are:
   - Missing (never created)
   - Stale (last modified before the most recent chunk that affected them)

2. **For each missing/stale artifact:**
   - Trivial fix → PM updates inline using `<dispatch:edit>`.
   - Non-trivial → dispatch the artifact's owner role with focused brief: "update <artifact> to reflect <changes>".

   **Artifact ownership** (canonical source: DESIGN §12.1; mirrors `roles/pm.md` "Artifact ownership summary" — inlined here so this recipe is self-contained):

   | Owner role | Artifacts |
   |---|---|
   | **PM** | VISION.md, REQUIREMENTS.md, PLAN.md, README.md, USER-GUIDE.md, RUNBOOK.md, CHANGELOG.md, LICENSE + NOTICE.md, SUPERHUMAN.md |
   | **Architect** | DESIGN.md, ARCHITECTURE.md, API.md, DATA-MODEL.md, DEPLOYMENT.md, THREAT-MODEL.md, DECISIONS.md, DEVELOPING.md |
   | **QA** | TEST.md |

   PM-owned artifacts that are trivial to update may be fixed inline (no dispatch); Architect/QA-owned artifacts go to their owner role when the update is non-trivial.

3. **Cross-artifact consistency pass.**
   - Do REQUIREMENTS IDs still match what was built?
   - Do DESIGN component names match the actual code?
   - Does README quick-start reflect the built behavior?
   - PM fixes inline or escalates.

4. **G7: Final docs review.**
   - Type A gate.
   - Present: diff of doc changes vs. last user-approved versions.
   - Recommendation: "approve and proceed to acceptance".

## Outputs

- All declared artifacts present, non-stale, internally consistent.

## Exit criteria

- G7 approved.
- Declared-artifacts check: ✓ all present and current.

Next phase: 3.3-preflight-review (pre-acceptance adversarial fan-out), then 4-acceptance.
