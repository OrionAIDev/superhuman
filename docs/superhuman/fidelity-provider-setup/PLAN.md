# Implementation plan: Superhuman fidelity + first-run provider setup

> **For agentic workers:** Implement this plan chunk-by-chunk — dispatch a fresh Developer subagent
> per chunk (foundation-first order), with a review checkpoint (Phase 3.1) between chunks.
> **Architect-drafted at G3; PM-finalized (2026-08-15).** Each chunk is TDD (failing test first) and
> ends with a commit that must pass the fast-test pre-commit gate.

**Goal:** Harden superhuman's own substrate for cross-session fidelity (#165) and provider-agnostic
first-run setup (#139) via document/template/role/phase edits plus one deterministic profile-script
extension.

**Architecture:** No new runtime. A new `conventions/` schema doc and two `SUPERHUMAN.md` template
sections are foundations; roles, orchestrator semantics, and the Phase-0 elicitation reference them.
The `models:` block of `~/.superhuman/profile.yaml` is generated by extending the existing
deterministic onboarding surface in `scripts/superhuman_profile.py`.

**Tech Stack:** Markdown (templates, roles, phase recipes, conventions, SKILL.md); Python 3
(`scripts/superhuman_profile.py`, stdlib + PyYAML per existing code); pytest.

**Chunking strategy:** foundation-first
**Value definition:** a chunk lands a substrate change a human can read and verify against a named FR,
with a deterministic check asserting its presence.
